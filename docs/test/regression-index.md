# Aether Gateway Production Issue Regression Index

Last updated: `2026-04-30`

This document records issues that have surfaced in real clusters, release validation, or pre-production testing, and maps each issue to a repeatable test or check item. The goal is to avoid relying solely on memory to catch recurring issues; when a new production issue is added, this index must be updated accordingly.

## Usage Rules

| Rule | Requirement |
| --- | --- |
| When to record | Immediately add or update an entry after discovering an issue in production, staging, Kind full-suite, release validation, or long-running tests. |
| Required fields | Symptom, root cause, fix commit, regression test or check, verification command, remaining uncovered risk. |
| Coverage judgment | An entry may only be marked as having regression coverage if there is a repeatable automated test, script check, or clearly defined manual check step. |
| Release usage | Before release, at minimum verify that the verification entry points for all `P0`/`P1` items in this document still exist, and confirm whether the latest release baseline covers them. |
| Exception handling | If an issue cannot be automated at present, you must clearly document manual reproduction steps, environment prerequisites, and gaps — do not simply write “to be added later”. |

## New Entry Template

| Field | Content |
| --- | --- |
| ID | `REG-<AREA>-<SHORT-NAME>`, e.g. `REG-XDS-ACK-STALE-NODE`. |
| Priority | `P0` means it causes unavailability, security escalation, or data misrouting; `P1` means high production risk but with a fallback or controllable impact scope. |
| Symptom | User-observable logs, status, HTTP/gRPC responses, metrics, or Kubernetes conditions. |
| Root Cause & Fix | Document the code path that caused the issue and the final fix strategy. |
| Fix Commit | Use short commit hash; if the fix spans multiple commits, list the representative ones. |
| Regression Test or Check | List test names, script names, or manual check items. |
| Verification Command | Provide a minimal command that can be directly copied and executed; expensive commands must note applicable scenarios. |
| Remaining Uncovered Risk | Clearly document which production environment dimensions are not yet covered by automation. |
